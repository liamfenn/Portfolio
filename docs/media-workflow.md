# Portfolio video foundation

## Import a finished clip

Keep the high-quality master. Export tagged SDR sRGB/Rec.709, with rotation baked in and the intended crop. A square master fits the homepage's square tiles. **Frame rate is preserved:** 60 stays 60, 59.94 stays 59.94, 30 stays 30. No default reduction to 30fps or upsampling. HDR/wide-gamut and missing color metadata stop with an actionable error rather than being silently retagged.

```bash
npm run media:import -- /path/to/master.mp4 --id shop-product-page --alt "Shop product page interaction prototype"
```

This single command:

1. Hashes the master and processing recipe to create versioned paths.
2. Encodes silent fast-start H.264 MP4 at 800/1200/1600px, omitting upscales and including the source width when it falls between rungs.
3. Preserves source frame rate as a constant rational rate, square pixels, even dimensions, and an SDR sRGB transfer/Rec.709 matrix. Quality settings are CRF 18/19/20 with slow encoding and one-second keyframe intervals.
4. Decodes each entire output to check for errors; verifies dimensions, frame rate, duration, and absence of audio. Writes a report with byte sizes and SHA-256 hashes. This checks integrity, not perceptual quality; inspect text, gradients, motion, and the loop on representative devices.
5. Produces 480/800/largest-width WebP posters from the same processed frame.
6. Uploads only missing files to public Vercel Blob. Paths are immutable and cached for one year. Existing output is reused only after matching the source/recipe and output hashes.
7. Atomically updates `src/lib/imported-media.json` with absolute public URLs, frame rate, dimensions, duration, posters, and renditions. The registry changes only after all uploads succeed.

`BLOB_READ_WRITE_TOKEN` is read from the environment or `.env.local`. Never commit it. Use `--local` to encode and validate without uploading or changing the deployed registry. Refer to a newly imported clip with `IMPORTED_MEDIA["your-id"]` in `src/lib/project-previews.ts`, then review, check, commit, and push the branch. Replacing `shop-product-page` updates its existing homepage alias automatically.

Options: `--fps 30` explicitly reduces the rate; it cannot exceed the source. `--widths 800,1200,1600`, `--poster-time 0.1`, `--assume-srgb` (only for a master known to be untagged SDR sRGB), and `--av1` (optional additional encodes). The grid currently selects H.264 for a consistent baseline. Optional AV1 output is reserved for later measured codec selection; there is no browser sniffing.

For local processing without registration:

```bash
npm run media:video -- /path/to/master.mov public/media/project/version-01
```

The old positional frame-rate/width arguments are rejected. Use named options. A recipe marker allows interrupted local processing to be retried; a different source or recipe requires a new output base. Completed outputs with valid hashes are reused. Masters and generated bytes remain out of Git; the small imported registry is committed.

## Grid playback

`ProjectPreviewVideo` renders an image poster and a native muted, looping, inline video with no source and `preload="none"`. Content stays visible before JavaScript, with reduced motion, with data-saving enabled, or when playback fails. Responsive posters load lazily and use automatic rendered-size selection where supported (with a viewport fallback); no third-party player or streaming library is shipped.

`src/lib/video-playback.ts` coordinates the whole page with shared visibility and resize observers:

- Sources are attached only for selected visible cards plus at most one upcoming card within 240px. At most two initial loads run simultaneously; those slots are released on decoded data, failure, cancellation, or a 15-second timeout. This limits startup work, not every browser byte-range request after buffering starts.
- At most four videos play on desktop and two on mobile. Hover/focus/expanded-card intent takes priority, then visible coverage and distance from viewport center. Paused cards retain their last decoded frame until their source is released; initial active loads retain a skeleton until presentation. Limits live in `video-policy.ts`; tune them with a full grid on real devices.
- The skeleton covers an initial active load until a video frame is presented and has had two paint opportunities, even if its poster has already loaded. The video stays visible beneath this opaque cover so startup does not unhide its native surface at the same moment coverage disappears. Pending paint callbacks cancel on pause/release. Posters are the fallback for reduced motion, data saving, denied/failed playback, unprepared cards, and no JavaScript. Normal buffering retains the last visible frame. Playback denial keeps a poster instead of retrying forever; renewed hover/focus/tap intent may retry. Load/decode failures get one automatic retry, then remain on the poster.
- Focus entry, paging, previews, scroll, and return keep the native media in its original grid subtree. `ProjectFocusMedia` owns fixed-position geometry and synchronized transforms, with scroll/resize work scheduled only when needed. It adds no duplicate media, canvas rendering loop, focus-time video pause, or destination shield. The overlay keeps only layout targets and metadata; tokenized layers keep native media below text/controls and above the backdrop. Cleanup restores original inline styles.
- Source upgrades wait until media motion settles. Only an actual rendition replacement captures one canvas (`project-preview-upgrade`) while the new source loads/seeks; its first presented frame plus paint opportunities removes that cover. Policy/error/disposal clear it too. This is independent of focus close, which never captures pixels or holds the video clock.
- Hidden pages and reduced-motion/data-saving changes release video sources immediately. Cards outside the prepared set pause; sources are released after 15 seconds. Cleanup removes observers, timers, and callbacks when the grid unmounts.
- Grid element width or settled focus-slot width × device pixel ratio (capped at 2×) selects the smallest adequate rung. Settled resize/expansion can upgrade; an attached video does not downgrade or reload on hover. Upgrades resume the playhead. Source rate is preserved in every rung.

Videos and posters share exact bounds and a single media clipping wrapper, without negative insets, video opacity transitions, or forced GPU promotion. An opaque alpha mask on that wrapper explicitly clips the independently composited video surface; it is a workaround for a reported screen-only edge artifact and still needs confirmation on the affected Mac/display. Grid transitions retain their existing outer transforms. Safari compositing artifacts must be verified in actual Safari, including after scroll, resize, expansion, and page backgrounding; a test WebKit browser is additional coverage, not a substitute for current iPhone/macOS Safari.

## Acceptance and incoming assets

Use 12 distinct assets to verify the real content mix. Start with four desktop/two mobile decoder slots, then tune only from measured results. Inspect first-frame time, initial bytes, byte-range behavior, dropped frames, memory after repeated scrolls, and visual quality. Repeat at DPR 1/2, desktop density settings, mobile expansion, throttled connections, blocked autoplay, failed media, reduced motion, and background/foreground. No video bytes should be requested in poster-only modes. Do not attach every source on page load.

The first 60fps clip is approximately 1.17/1.80/2.28 MB at 800/1200/1600px for 14.78 seconds. These are reference measurements, not guaranteed budgets for other content. Preserve detail and motion; flag unusually large outputs for review rather than silently degrading them. Byte size and lossless decode checks do not establish cross-device performance or visual fidelity.

The old `media:upload` bulk script remains a legacy utility for existing media; new clips use `media:import` and immutable paths. Public CDN delivery supports range requests; the import manifest uses complete URLs so Preview and Production do not depend on a missing `NEXT_PUBLIC_MEDIA_BASE_URL`.

## Repeatable browser checks

`/dev/video-lab` renders twelve independently fetched copies of the current clip with density and priority controls, and returns 404 outside development. It is a synthetic concurrency check, not validation of twelve different finished clips.

With the optional Playwright tooling already used by the capture scripts and a WebKit browser installed, run:

```bash
node scripts/check-video-grid.mjs http://localhost:3001
```

This checks desktop/mobile decoder and initial-load limits, priority, upgrades, delayed source release, a simulated hidden-page event, reduced-motion changes, encoded-frame presentation, rendered edge pixels through fractional scrolling, and poster fallbacks. It reports first-frame observations and frame counters for investigation; headless timing and screenshot-induced dropped frames are not real-device performance benchmarks. Reduced-motion, data-saving, and JavaScript-disabled contexts assert zero video requests. Playback-denial and network-failure contexts assert retries stop. `VIDEO_CHECK_FALLBACKS_ONLY=1` reruns only those fallback cases.

`node scripts/check-focus-regressions.mjs [origin]` uses real H.264 playback in WebKit to check delayed-video skeletons, held-frame upgrades (including closing mid-upgrade), text removal after paging/close, and successive trackpad-style strokes without a pointer move or a full momentum pause. Native Safari compositing remains a device check.

`node scripts/check-focus-exit-order.mjs [origin]` checks that controls disappear before the 180ms bottom-to-top fades with 12ms stagger, and that no return movement begins while focus text remains, after paging and vertical scrolling, for video/placeholder cards and different grid widths. Set `FOCUS_BROWSER=chromium` to repeat the default WebKit checks in Chromium. Focus exit completes the control fade, all row fades/removal, and a paint opportunity before measuring and starting the media return; scrolling stays locked until close.

The [focus media audit](focus-media-audit.md) records the investigated lifecycle boundaries and external implementations. The stable-DOM controller is now integrated; automated frame continuity does not certify native Safari compositing.

`node scripts/check-video-startup-paint.mjs [origin]` holds a real WebKit video-frame callback across initial load and repeated reloads. It checks opaque skeleton coverage over a visible video surface, two paint opportunities before reveal, and policy cancellation of a stale reveal. This checks the lifecycle, not a physical iPhone compositor flash.

`node scripts/check-focus-video-continuity.mjs [origin]` checks real WebKit frames through repeated rapid/scrolled exits and both paging directions. It asserts unchanged media parents, no close-time pause/source load/canvas/duplicate, scroll/resize alignment, resize during return, and reduced-motion/background/foreground cleanup. The former clock-hold/handoff tests and isolated probe have been replaced by this integrated check.

`node scripts/check-focus-stacking.mjs [origin]` checks focus panels above background menus and globe glyphs on desktop/mobile, including a scrolled footer. It briefly enables inert background hit testing to detect incorrect paint order that normal interaction checks miss. Set `FOCUS_BROWSER=chromium` to repeat the default WebKit check in Chromium.
